## BE1 ↔ AI 질문 생성 연동 명세

### 역할

- **BE1:** 선택 감정, 사용자가 수정·확인한 일기 본문, 이전 질문·답변을 AI에 전달한다.
- **AI 담당:** 질문 순서에 맞춰 이전 답변을 반영한 질문 1개를 생성한다.
- **BE1:** 생성된 질문을 저장하고 프론트에 전달한다. 사용자가 답변을 확인하면 저장한 뒤 다음 질문을 요청한다.

### 질문 순서

| 순서 | 질문 유형 | 목적 |
| --- | --- | --- |
| 1 | `EMOTION` | 감정 탐색 |
| 2 | `REASON` | 감정을 느낀 이유 탐색 |
| 3 | `PERSPECTIVE` | 다른 관점으로 생각해 보기 |

### BE1 → AI 요청

아래는 첫 번째 답변을 저장한 후 **두 번째 질문을 요청하는 예시**다.

```
{
  "emotion": "JOY",
  "content": "오늘 친구와 운동장에서 공놀이를 했다. 친구가 나에게 공을 넘겨줘서 골을 넣었다.",
  "order": 2,
  "type": "REASON",
  "previousAnswers": [
    {
      "order": 1,
      "type": "EMOTION",
      "question": "골을 넣었을 때 어떤 기분이 들었니?",
      "answer": "정말 신나고 친구한테 고마웠어요."
    }
  ]
}
```

| 필드 | 전달 규칙 |
| --- | --- |
| `emotion` | 사용자가 선택한 감정 코드 |
| `content` | 음성 인식 또는 직접 입력 후 사용자가 수정·확인한 일기 본문 |
| `order` | 생성할 질문 순서. `1`, `2`, `3` 중 하나 |
| `type` | 순서에 맞는 질문 유형. `EMOTION`, `REASON`, `PERSPECTIVE` |
| `previousAnswers` | 앞선 질문과 확정된 답변을 순서대로 전달 |
| `question` | 사용자에게 실제로 보여준 질문 |
| `answer` | 사용자가 수정·확인한 최종 답변 |
- 첫 번째 질문 요청: `previousAnswers: []`
- 두 번째 질문 요청: 첫 번째 질문·답변 포함
- 세 번째 질문 요청: 첫 번째와 두 번째 질문·답변 포함
- 감정 코드: `JOY`, `SADNESS`, `ANGER`, `FEAR`, `SURPRISE`, `SHAME`

### AI → BE1 응답

```
{
  "order": 2,
  "type": "REASON",
  "content": "친구가 공을 넘겨줬을 때 왜 고마운 마음이 들었니?"
}
```

| 필드 | 생성 규칙 |
| --- | --- |
| `order` | 요청받은 질문 순서와 동일 |
| `type` | 요청받은 질문 유형과 동일 |
| `content` | 일기 본문과 이전 답변에 연결되는 질문 1개 |

`questionId`는 AI가 만들지 않고 BE1이 DB에 저장하면서 부여한다. `isFallback`도 BE1이 기본 질문 사용 여부에 따라 설정한다.

### AI 생성 규칙

- 아이가 이해하기 쉬운 한국어로 짧고 부드럽게 작성한다.
- 한 번에 질문 1개만 반환한다.
- 질문 순서에 맞는 목적을 따른다.
- 일기 본문과 이전 답변을 반영하고, 이미 답한 내용을 반복해서 묻지 않는다.
- 사용자가 선택한 감정을 임의로 변경하지 않는다.

## BE2 ↔ AI 감정 리포트 연동 명세

### 역할

- **BE2:** 선택 기간의 완료된 일기를 조회해 감정별 건수·비율과 날짜별 감정 기록을 계산한다.
- **AI 담당:** 전달받은 데이터를 바탕으로 감정 분포 설명, 보호자 한 줄 조언, 변화 추이 해석을 생성한다.
- **BE2:** AI 응답을 통계 데이터와 합쳐 `GET /api/reports/emotions`의 응답으로 프론트에 전달한다.

### BE2 → AI 요청

```
{
  "startDate": "2026-11-01",
  "endDate": "2026-11-03",
  "totalDiaryCount": 3,
  "distribution": [
    { "emotion": "JOY", "count": 2, "ratio": 66.67 },
    { "emotion": "SADNESS", "count": 1, "ratio": 33.33 },
    { "emotion": "ANGER", "count": 0, "ratio": 0 },
    { "emotion": "FEAR", "count": 0, "ratio": 0 },
    { "emotion": "SURPRISE", "count": 0, "ratio": 0 },
    { "emotion": "SHAME", "count": 0, "ratio": 0 }
  ],
  "days": [
    { "date": "2026-11-01", "emotions": ["JOY"] },
    { "date": "2026-11-02", "emotions": ["SADNESS"] },
    { "date": "2026-11-03", "emotions": ["JOY"] }
  ]
}
```

| 필드 | 전달 규칙 |
| --- | --- |
| `startDate`, `endDate` | 조회 기간. 시작일·종료일 모두 포함 |
| `totalDiaryCount` | 해당 기간의 완료된 일기 수. 삭제한 일기 제외 |
| `distribution` | 감정 6종 모두 전달. 기록이 없는 감정도 0건으로 포함 |
| `ratio` | 전체 일기 중 해당 감정의 비율(%), 소수 둘째 자리까지 |
| `days` | 기간 내 모든 날짜를 날짜순으로 전달 |
| `emotions` | 해당 날짜의 일기별 감정. 미작성일은 `[]`, 여러 일기는 중복 감정도 유지 |

### AI → BE2 응답

```
{
  "description": "선택한 기간에는 기쁨을 가장 자주 기록했어요.",
  "advice": "아이와 즐거웠던 순간을 이야기하고, 슬펐던 날의 마음도 편안하게 들어 주세요.",
  "interpretation": "기쁨과 슬픔을 기록했고, 마지막 기록은 기쁨이었어요."
}
```

| 필드 | 생성 규칙 |
| --- | --- |
| `description` | 감정 분포 설명. 1~2문장 |
| `advice` | 보호자에게 전달하는 구체적인 조언. 1문장 |
| `interpretation` | 날짜별 감정 변화에 대한 설명. 1~2문장 |

### AI 생성 규칙

- 전달받은 기록에 근거해서 한국어로 작성한다.
- 통계 수치는 다시 계산하거나 변경하지 않는다.
- 기록에 없는 사건·원인·아이의 상태를 추측하지 않는다.
- 정신건강 진단이나 감정이 좋아졌다·나빠졌다는 단정을 하지 않는다.
- 기록이 적으면 장기적인 변화가 있다고 해석하지 않는다.
- 응답은 위 세 필드를 가진 JSON으로 반환한다.

### 예외 처리

- **일기 0건:** BE2가 AI를 호출하지 않고 다음 문구를 반환한다.

```
{
  "description": "선택한 기간에 작성된 일기가 없어요.",
  "advice": "아이와 오늘의 기분을 이야기하며 첫 일기를 남겨 보세요.",
  "interpretation": "감정 기록이 없어 변화 추이를 확인할 수 없어요."
}
```

- **AI 호출 실패·응답 형식 오류:** 통계는 그대로 반환하고 BE2가 기본 문구를 넣는다.

```
{
  "description": "선택한 기간의 감정별 기록을 확인해 주세요.",
  "advice": "아이의 감정 기록을 보며 이야기를 들어 주세요.",
  "interpretation": "날짜별 감정 기록은 그래프에서 확인할 수 있어요."
}
```

### AI 담당과 확정할 사항

이 요청·응답 JSON을 공통 규격으로 사용한다. 별도 AI 서버라면 호출 주소·인증 방식·제한 시간을, 백엔드 내부 함수라면 함수 이름·입출력 형식을 추가로 합의한다. 이 연동은 프론트가 직접 호출하지 않는다.
